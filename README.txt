เว็บแอพกิจกรรมตอบคำถาม 5ส – WH FG ถุง

สำคัญ: ไฟล์ ZIP เป็นซอร์สโค้ดพร้อมติดตั้ง ยังไม่ใช่เว็บออนไลน์ที่เปิดใช้งานทันที เพราะต้องเชื่อม Supabase และกำหนดรหัสผ่าน Admin ก่อน

ขั้นตอน 1 – สร้างฐานข้อมูล
1. เข้าสู่ https://supabase.com/dashboard และสร้าง Project
2. ไปที่ SQL Editor > New query
3. คัดลอกไฟล์ setup.sql ทั้งหมด แล้วกด Run (ครั้งเดียว)
4. ไปที่ Project Settings > API Keys คัดลอก secret/service_role key (ห้ามแชร์หรือใส่ในหน้าเว็บ)
5. คัดลอก Project URL

ขั้นตอน 2 – ตั้งค่า Netlify
1. แตกไฟล์ ZIP ในคอมพิวเตอร์
2. อัปโหลดโฟลเดอร์โครงการขึ้น GitHub repository ส่วนตัว
3. ไปที่ https://app.netlify.com > Add new project > Import an existing project > GitHub
4. เลือก repository ของโครงการ
5. Build command: เว้นว่าง หรือ npm install (Netlify ติดตั้ง dependencies อัตโนมัติ)
6. Publish directory: public / Functions directory: netlify/functions (มีใน netlify.toml)
7. ใน Site configuration > Environment variables เพิ่ม:
   SUPABASE_URL = Project URL
   SUPABASE_SERVICE_ROLE_KEY = secret/service_role key
   ADMIN_PASSWORD = รหัสผ่าน Admin ที่ตั้งเอง (ควรยาวและคาดเดายาก)
8. กด Deploy / Trigger deploy ใหม่หลังตั้งค่า
9. เปิดลิงก์ Netlify เพื่อทดสอบการตอบ และคลิก 'สำหรับผู้ดูแลระบบ' เพื่อเข้าหน้า Admin

สำคัญ: ไม่ควรใช้ Netlify แบบลากวางโฟลเดอร์ public อย่างเดียว เพราะระบบนี้ต้องใช้ Functions และ dependencies ฝั่งเซิร์ฟเวอร์

การใช้งาน
- ผู้ดูแลแก้ไขคำถามและเฉลยในหน้า Admin ก่อนให้พนักงานเริ่มตอบ
- คำถามตัวอย่าง 15 ข้อมีให้แล้ว แก้ให้ตรงมาตรฐานจริงของแผนกก่อนเปิดใช้
- ระบบใช้รหัสพนักงานเป็นตัวจำกัดการส่ง 1 ครั้ง (ไม่ใช่การยืนยันตัวตนอย่างเป็นทางการ หากรู้รหัสคนอื่นอาจแอบตอบแทนได้)
- คะแนนไม่แสดงให้พนักงานเห็นหลังส่ง
- Admin ดูอันดับและดาวน์โหลด CSV เปิดด้วย Excel ได้
- วันปิดรับเริ่มต้น 27 ต.ค. 2569 เวลา 00:00 น. ตามข้อความที่ให้มา หากต้องการรับถึง 27 ต.ค. 23:59 ให้เปลี่ยนเป็น 28 ต.ค. 2569 00:00 น. ในหน้า Admin
- ไม่ควรแก้คำถามเมื่อมีผู้ตอบแล้ว ระบบล็อกการแก้ไข

ความปลอดภัย
- ไม่ใส่ secret/service_role key ใน public หรือ GitHub
- หน้า Admin ใช้รหัสผ่านจาก Environment Variables และ token อายุ 1 ชั่วโมง
- การจำกัด 1 ครั้งอาศัย unique constraint ของรหัสพนักงานในฐานข้อมูล
- แนะนำให้ตั้งรหัสผ่าน Admin แข็งแรงและจำกัดการเผยแพร่ลิงก์
- สำหรับความปลอดภัยระดับองค์กร ควรเพิ่มการยืนยันตัวตนพนักงานและ rate limiting ก่อนใช้งานในวงกว้าง


การปรับปรุง: เลือกชื่อจากรายชื่อพนักงาน (ไม่ต้องใช้ Email)
- เปิดเว็บแล้วเลือกชื่อจากรายการที่ Admin จัดเตรียมไว้ ไม่ต้องกรอกอีเมลหรือรหัสพนักงาน
- ในหน้า Admin มีส่วน "จัดการรายชื่อพนักงาน" เพิ่ม/ลบชื่อที่เปิดให้เลือกได้ โดยพิมพ์ชื่อ 1 คนต่อบรรทัด
- รายชื่อเริ่มต้น 19 คนเป็นตัวอย่างจากรายชื่อแผนก โปรดตรวจสอบและปรับก่อนใช้งาน
- ระบบจำกัดการส่ง 1 ครั้งต่อรหัสรายการชื่อในฐานข้อมูล (ใช้ unique constraint)
- ข้อจำกัดสำคัญ: การเลือกชื่ออย่างเดียวไม่สามารถพิสูจน์ตัวตนได้ ใครก็ตามที่รู้ชื่ออาจเลือกตอบแทนคนอื่นได้ ถ้าต้องการป้องกันจริงควรเพิ่ม PIN ลับรายคนหรือการตรวจสอบจากผู้ดูแล
- ถ้าเคยติดตั้งเวอร์ชันเดิมแล้ว ให้รันเฉพาะส่วน SQL ตั้งแต่บรรทัด "-- รายชื่อพนักงาน" ใน setup.sql เพิ่มใน SQL Editor เพื่อไม่กระทบข้อมูลเก่า
- หากเคยส่งคำตอบในเวอร์ชันก่อน รหัสพนักงานเดิมกับรหัสรายการชื่อใหม่อาจไม่ตรงกัน ให้ตรวจสอบผลเดิมก่อนเปิดใช้งาน
